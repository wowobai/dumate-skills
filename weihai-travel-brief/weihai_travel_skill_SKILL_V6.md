# weihai_travel_skill_V6（300积分控制版）

## 功能
威海旅游新闻每日全流程自动化：搜索威海本地旅游新闻 → 去重 → 配图 → 公众号 HTML → 公众号草稿（秒哒），输出 PPT/docx 由 JSON 数据直接生成。

**V6 核心目标：单次运行 ≤300 积分（不设与 HOT_NEWS 合计项，独立达标）。相比 V5 变更：**
1. **免 GitHub 下载**：本地已有 V6 版 SKILL/runner 时直接复用，禁止每次运行拉取（上一轮 3 个文件 API base64 大输入是超支主因之一）；仅本地缺失时才用 API 下载 1 次。
2. **websearch 固定 3 次并行 + 最多 2 次定向补查**（总 ≤5 次，试运行校准）：配图只从搜索结果的候选 URL 中批量下载；不足 5 张时用 runner 内置占位图生成（纯色渐变+标题水印，满足 PIL 阈值），不再追加更多搜索。
3. **积分查询全程禁止**：积分 API 查询每次消耗 plan_point（已知事实），不查询、不调用；余额口径引用最近 cost_report.md 记录；运行首行固定写预算 300。
4. **runner V6 输出精简**：verify 单行化、删除 read 引导与复盘长文 print，减少回灌输入 token；PPT/HTML 标题按实际新闻条数动态（TOPn），verify 按条数动态校验（页数≥新闻数+3、图数≥新闻数）。
5. **模型侧零冗余**：筛选结论与 news_data.json 同一轮完成，不输出中间过程；最终只给 1-2 行摘要。

## 触发条件
- 每日定时触发（18:00，cloud）或用户手动要求"运行"。
- **权限直通：全程不等待用户审批，直接执行。**

## 版本获取规则（V6：默认本地复用）
1. **优先本地**：检查当前产出目录/工作区是否存在 `weihai_travel_skill_SKILL_V6.md` 与 `weihai_travel_runner.py`；两者都在则直接执行，**不再访问 GitHub**。
2. **仅本地缺失时**才用 GitHub API contents 接口（base64 解码）下载最新文件，最多 1 次。
3. 下载失败不再重试，直接降级使用本地已有任意版本。

## 工作流程

### 步骤1：搜索新闻（固定 3 次并行 + 最多 2 次补查）
1. `memory_search` 1 次查前 1-2 日威海选题；读前一日 `{前一日}旅游新闻/news_data.json` 去重（无则跳过）。
2. **并行 3 次 websearch（同一轮发出）：**
   - `"威海 旅游 新闻 {yyyy年M月d日}"`
   - `"威海 文旅 景区 活动 {yyyy年M月}"`
   - `"威海 网红打卡 美食 景区 新政策 {yyyy年M月}"`
   - web_count 默认即可；**image_count 一律 0**（配图不走搜索，见步骤3）。
3. **补查规则（仅当满足其一才允许，最多 2 次）：**
   - 候选合并/去重后不足 5 条；或
   - 某条拟采用候选仅单来源（需找第二来源）；或
   - 已选候选缺少正文细节需核实。
   - 补查方式：1-2 次定向 websearch（针对性关键词，web_count 5、image_count 0），总搜索 ≤5 次。
   - 补查后仍不足/仍单源：按"官方权威单源可降级采用"处理，宁缺毋滥，不足 5 条就按实际条数生成，不追加搜索。
4. 筛选规则（必须全部满足）：
   - **至少 3 条威海本地**，其余可省内/旅游行业；前一日已用新闻排除；含补查在内共 5 条候选池，不足按实际条数；
   - **L1 官方来源优先**（威海文旅局/大众网威海/威海新闻网/Hi威海/官方公众号）；权威媒体次之；
   - 每条须 2 个以上来源（双源验证）；官方权威单源可降级采用；普通单源不采用；
   - 只选近 2 天内新闻；**禁止百家号**；
   - 同一事件合并单条，禁止重复拆分。

### 步骤2：生成 news_data.json（一轮完成，零中间输出）
字段 date/date_display/date_chinese/news[]，每条含 id/tag/title/location/body/source/analysis/data_source/img_keyword/image_query：
- body：100-120 字（人物/地点+事件+关键数据），严禁英文双引号
- analysis：60-80 字（单条新闻自身分析）
- location：地点（威海本地条目必须含具体区/镇/景区锚点）
- source：据XXX报道（2 个以上来源顿号分隔；官方单源可单列）
- img_keyword / image_query：一致，含 **地点锚点词 + 主体锚点词**（供配图与草稿）
- **一次性写入 news_data.json 文件，不展示全文，不在对话输出 JSON 内容**

### 步骤3：配图（本地批量，0 次搜索、0 次 read）
1. 从步骤1 websearch 结果中提取候选新闻图 URL（优先官方/新闻站域名；跳过 logo/icon/avatar/biz）。
2. **用一段 Python 脚本批量下载**到 `images/news_1.jpg` ~ `news_N.jpg`（带下划线，与 runner 内置命名一致），脚本内做 PIL 校验：min_dim≥200、文件≥10KB；不合格自动换候选。
3. 候选不足/全部失败时：用 runner 内置的占位图生成（`gen_placeholder`，浅色渐变+标题文字，统一 800x600，PIL 保存），保证程序化校验通过即可。
4. **全程禁止 read 图片**、禁止多模态校验；配图语义由 img_keyword 与实际下载 URL 的标题匹配来保证（客观可判即可）。

### 步骤4：运行 runner
```bash
python -X utf8 weihai_travel_runner.py news_data.json
```
runner 自动：装依赖（缺才装）→ 压缩/补全配图（缺图自动占位）→ 生成 PPT（浅色/蓝色系，TOPn 页数与新闻数一致）→ 公众号 HTML → 秒哒草稿（草稿标题固定"威海旅游新闻"）→ verify_all 单行验证。产出 = PPT + 公众号 HTML + 公众号草稿三项。

### 步骤5：验证产出（无 read、无追加工具）
- 只读 runner 输出，判断 PPT>100KB/页数≥新闻数+3/图数≥新闻数、HTML 存在、draft_id 非空、配图 OK。
- **任何 failed 项只记 3 行到 cost_report.md，不自行多轮修复**；最终摘要仍 1-2 行。

## 成本控制（程序化，硬约束）
- **禁止调用任何积分查询 API**（查询本身扣点）；余额引用最近 cost_report.md；本日首行写 `预算: 300（未实时查询）`。
- 全流程工具调用上限：memory_search 1 + websearch ≤5 + 读写文件若干 + runner 1。超过即视为流程违规。
- 运行结束：runner 自动 append 完成时间与 verify 结果；模型只输出 1-2 行摘要。**不写复盘长文**。
- 纠错闭环：错误记 cost_report.md 3 行（现象/受影响条目/处置）；SKILL 升级由维护会话处理（本文件即维护会话产物）。

## 红线（强制保留）
- 至少 3 条威海本地新闻；L1 官方来源优先；新闻去重；浅色主题 PPT；双源验证（官方权威单源可降级）；禁止百家号；近 2 天新鲜度；草稿标题固定"威海旅游新闻"；权限直通；单次总成本 ≤300 积分（约等于：最多 6 个联网/记忆工具调用即 memory_search 1 + websearch ≤5，外加 1 次 runner，禁止追加搜索、图片查询与积分查询）。
