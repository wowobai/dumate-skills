# weihai_travel_skill_V6.6（300积分控制版）

## 功能
威海旅游新闻每日全流程自动化：取权威本地源新闻 → 去重 → 配图 → 公众号 HTML → 公众号草稿（秒哒），输出 PPT/docx 由 JSON 数据直接生成。

**V6.4 主路径改造（本版核心）：**
1. **选题主路径 = webfetch 直取权威本地源**（不再用 websearch 泛词）。固定并行抓取 `http://www.whnews.cn/`（威海新闻网，市新闻传媒中心官方）与 `http://weihai.iqilu.com/`（齐鲁网威海，山东广电）的首页/要闻/民生/区市/镇街/部门/文体列表页，直接读到带日期的当日及近 2 日本地新闻标题与正文；命中率远高于泛词搜索（实测泛词 5 次中后 3 次基本无效，webfetch 一次批量即得 4-5 条可用）。
2. **websearch 降为可选补充**（≤2 次）：仅在 webfetch 结果不足 5 条、或需为单源条目找第二来源、或需权威政策类补充时使用，用「官方发布/文旅局/景区公告」等强权威词。
3. **配图 = 从权威新闻正文页直取**（`img12.iqilu.com` / `img8.iqilu.com` / `www.whnews.cn/news/data/`），**取消图片搜索通道**（实测一次全部命中，省调用且命中率 100%）。

**V6.5 第N次运行原则（硬性·窗口/去重/替榜，所有资讯类 skill 通用）：**
1. **搜索窗口以本次运行时刻为准**：从「前一天最后一次运行时刻」起到本次运行时刻之间的新闻；**若前一天无运行记录，则截止节点改为「前两天最后一次运行时刻」**；**最多回溯至前三天（最早取到 T-3 日）**。窗口内各日期新闻均可选题。
2. **去重口径（关键）**：**当天新闻不去重**（同一天多次运行可复用当日条目）；**前一天的新闻采取去重**——去重集 = `glob` 全部历史产出目录 `*旅游/news_data.json`，凡前序各日已采用的条目（标题/事件）一律排除。
3. **同日多次运行的替榜**：按「热度新闻影响（事件量级/覆盖媒体数）+ 在榜持续时间」综合排序；若发现**持续时间更久、热度更大**的事件，**及时替换掉已经掉榜的旧条目**；头条优先给持续发酵、覆盖更广的顶流事项。
4. **持续优化**：每次运行若发现更优/命中率更高的进程，**立即固化进本 SKILL 与 runner**，确保**下次运行 ≤300 积分**，并**同步 GitHub 与秒哒**。

**V6.6 配图取用与错配防护（硬性·重点）：**
1. **同源优先（防错配核心）**：每条配图必须取自该条新闻**自身**的权威正文页（同事件、同来源）；**严禁跨条/跨文章取图**——拿其他文章、其他活动的图充当本条配图即属「图文错配」（重大错误，本次事故根因）。
2. **三级回退**：① 优先取自身正文页的**活动实拍图**；② **无法取得活动实拍图时，改用正文中提到的无商标实物图**——即新闻正文里出现的本地特色美食/产品（如海参、水饺等）的**实物照片**，必须**无品牌 Logo、无商户招牌、无第三方水印**；③ 以上都不可得时，才用 runner 内置 `gen_placeholder` 生成占位图。
3. **禁用清单（命中即弃）**：带品牌/商户 Logo 的图；竞赛、会展**展位图**（如「太太乐·第十届全国烹饪技能竞赛」展位）；含第三方水印的图（如「胡杨文旅工作室」「千里山海」）；与条目事件明显不符的外地图/外地赛事图。**唯一例外（仍属同源、可用）**：该条新闻**自身**的广播电视播出截图（画面自带播出台标/字幕条），在与本条同事件、且无更干净的同类图源时可用——它仍属该条同源素材；但**严禁**把无关栏目/他项活动的台标截图当本条配图。
4. **定稿核验**：下载前核对图源 URL 是否属于该条正文页；对活动/美食/赛事等**易错配条目**，把握不准时允许对**至多 1 张**关键配图做 1 次 `read` 目视核验，确认图片主体与标题/正文一致后再定稿（本地操作，从严限制次数以免超 300 分）。
5. **PPT 配图尺寸修复（V6.6 代码修复，必做回归）**：runner `gen_ppt` 原按 `Inches(iw * ratio / 72)` 计算图片宽高，**多除了 1 个 72**，致配图仅约 0.06 英寸、渲染后**近乎不可见**（历史版本通病，因历来只比对内嵌媒体字节、未渲染，长期未被发现）。V6.6 起改为按 **4.5×4.5 英寸图框等比缩放**（`scale = min(4.5/iw, 4.5/ih)`；宽 = `iw*scale` 英寸，图框内垂直居中）。定稿后**必须**用 `soffice --headless --convert-to pdf` + `pdfimages -list` 抽查：各内容页内嵌图应接近原始像素尺寸（如 1080×640 / 1200×675），**不得**出现十几像素的小图。

**V6.2 补充规则（民生补足）：旅游新闻确实凑不齐 5 条时，可用威海本地民生新闻补足至 5 条；但头条（第 1 条）必须与旅游相关。**

**V6.3 标题规则（硬性）：公众号草稿总标题有且只有一个，且必须是带日期的「威海旅游新闻」——格式为「新闻日期 + 半角空格 + 威海旅游新闻」（例「2026年10月25日 威海旅游新闻」），由秒哒端 create-draft 按 `${date_display} ${main_title}` 生成；正文开头不得再输出任何标题文字，只保留一行日期，确保草稿箱中标题只出现一次。**

**V6 核心目标：单次运行 ≤300 积分（不设与 HOT_NEWS 合计项，独立达标）。**
1. **免 GitHub 下载**：本地已有 SKILL/runner 时直接复用，禁止每次运行拉取；仅本地缺失时才用 API 下载 1 次。
2. **工具口径（V6.4 重定义）**：`memory_search 1 + webfetch ≤6（主源）+ websearch ≤2（仅补充）+ 读写文件若干 + runner 1`。webfetch 不消耗搜索积分，故以 webfetch 替代泛词 websearch 是省分且提命中率的最优解。
3. **积分查询全程禁止**：积分 API 查询每次消耗 plan_point（已知事实），不查询、不调用；余额口径引用最近 cost_report.md 记录；运行首行固定写 `预算: 300（未实时查询）`。
4. **runner V6 输出精简**：verify 单行化、删除 read 引导与复盘长文 print；PPT/HTML 标题按实际条数动态（TOPn），verify 按条数动态校验（页数≥新闻数+3、图数≥新闻数）。
5. **模型侧零冗余**：筛选结论与 news_data.json 同一轮完成，不输出中间过程；最终只给 1-2 行摘要。

## 工作流程

### 步骤1：取新闻（webfetch 主源，≤6 次）
0. **确定搜索窗口（第N次运行原则）**：以本次运行时刻为准，回溯至「前一天最后一次运行时刻」；前一天无运行记录时，截止节点改为「前两天最后一次运行时刻」；**最多回溯至前三天（T-3）**。以产出目录命名（`YYYYMMDD旅游`，取日期最大者即上一运行日）判定前一次运行时刻。
1. `memory_search` 1 次查前 1-2 日威海选题。
2. **去重自动化**：`glob` 扫描工作区 `*旅游/news_data.json`，一次性读取全部历史产出目录的已用新闻（标题+地点）作为排除集（不再只读前一日）；**当天新闻不去重、前一天新闻去重**（见 V6.5）。
3. **并行 webfetch 直取权威本地源（同一轮发出，≤6 个）：**
   - `http://www.whnews.cn/`（首页/今日威海/民生/区市/镇街）
   - `http://weihai.iqilu.com/`（首页/威海要闻/时政/民生）
   - 需要时补抓栏目文章页 `https://weihai.iqilu.com/<栏目>/2026/10DD/xxxxxxx.shtml`、`https://mp.weixin.qq.com/s?...`（官方公众号文章页，webfetch 可返回正文）。
   - **已知废弃源（禁止使用）**：`whnews.cn/news/node_27586.htm`（文旅频道，内容陈旧）；`v.iqilu.com/qlpd/mrxw/*.html`（视频页，webfetch 仅返回导航壳，正文不可得）。
4. **补充规则（仅当满足其一，≤2 次 websearch）**：候选去重后不足 5 条 / 某条仅单来源 / 缺正文细节。
5. 筛选规则（必须全部满足）：
   - **至少 3 条威海本地**，其余可省内/旅游行业；历史已用新闻排除；共 5 条候选池；
   - **【补充规则·民生补足】** 旅游新闻凑不齐 5 条时可用威海本地**民生新闻**补足；但**头条（第 1 条）必须与旅游相关**；民生条目 tag 统一记「本地·民生」，并同样满足来源/时效/去重要求；
   - **L1 官方来源优先**（威海文旅局/威海新闻网/Hi威海/齐鲁网威海/官方公众号）；权威媒体次之；
   - 每条须 2 个以上来源（双源验证）；官方权威单源可降级采用；普通单源不采用；
   - 只选近 2 天内新闻；**禁止百家号**；
   - 同一事件合并单条，禁止重复拆分。

### 步骤2：生成 news_data.json（一轮完成，零中间输出）
字段 date/date_display/date_chinese/news[]，每条含 id/tag/title/location/body/source/analysis/data_source/img_keyword/image_query：
- body：**约 100-130 字**（实测 102-128 为佳；人物/地点+事件+关键数据），严禁英文双引号（用「」或""）
- analysis：60-80 字（单条新闻自身分析）
- location：地点（威海本地条目必须含具体区/镇/景区锚点）
- source：据XXX报道（2 个以上来源顿号分隔；官方单源可单列）
- img_keyword / image_query：一致，含 **地点锚点词 + 主体锚点词**
- **一次性写入 news_data.json 文件，不展示全文，不在对话输出 JSON 内容**
- **date_display 必须为「YYYY年M月D日」中文格式**（草稿总标题前缀即取此值）

### 步骤3：配图（同源直取 + 三级回退，见 V6.6）
1. 从步骤1 webfetch 到的**该条新闻自身正文页**提取正文图 URL（`img12.iqilu.com` / `img8.iqilu.com` / `www.whnews.cn/news/data/` 等；跳过 logo/icon/avatar/biz）；**严禁跨条/跨文章取图**。
2. **用一段 Python 脚本批量下载**到 `images/news_1.jpg` ~ `news_N.jpg`（下载需 `verify=False` + UA 头；PIL 转 JPEG），脚本内做 PIL 校验：min_dim≥200、文件≥10KB；不合格自动换候选。
3. **回退顺序（V6.6）**：① 自身正文页**活动实拍图** → ② 无活动实拍图时，改用**正文中提到的无商标实物图**（本地特色美食/产品，如海参、水饺等；**不得带品牌 Logo、商户招牌或第三方水印**）→ ③ 仍不可得才用 runner 内置 `gen_placeholder` 生成占位图（浅色渐变+标题文字），保证程序化校验通过。
4. **禁用**：品牌 Logo 图、会展/竞赛展位图、含第三方水印图、与条目事件不符的外地图/外地赛事图（**同源例外**：该条新闻自身的播出截图带台标/字幕条时可用）。**定稿前核对图源 URL 是否属于该条正文页**；对活动/美食/赛事等易错配条目，把握不准时允许对**至多 1 张**关键图做 1 次 `read` 目视核验（从严控制次数，避免超 300 分）。

### 步骤4：运行 runner
```bash
python -X utf8 weihai_travel_runner.py news_data.json
```
runner 自动：装依赖（缺才装）→ 压缩/补全配图（缺图自动占位）→ 生成 PPT（浅色/蓝色系，TOPn 页数与新闻数一致）→ 公众号 HTML → 秒哒草稿（**草稿总标题有且只有一个且带日期**，由服务端 create-draft 按 `${date_display} ${main_title}` 生成；正文不重复标题、仅一行日期；runner 传真实 date_display 与 main_title="威海旅游新闻"）→ verify_all 单行验证。产出 = PPT + 公众号 HTML + 公众号草稿三项。
> `hot_news_runner.py`（凭据载体）必须与 `news_data.json` 同目录，供 runner 回退提取凭据。

### 步骤5：验证产出（不追加搜索工具）
- 只读 runner 输出，判断 PPT>100KB/页数≥新闻数+3/图数≥新闻数、HTML 存在、draft_id 非空、配图 OK。
- **核对草稿总标题：有且只有一个，且形如「YYYY年M月D日 威海旅游新闻」**（`draft_title` 应为日期 + 空格 + 主标题），不符即失败。
- **核对配图同源与图文一致**：确认各图取自对应条目正文页、主体与标题相符（见 V6.6）。
- **核对 PPT 配图真实可见（V6.6 新增）**：定稿后 `soffice --headless --convert-to pdf` + `pdfimages -list` 抽查，各内容页内嵌图尺寸须为原始像素级（不得出现十几像素小图）；必要时抽 1 页渲染图目视确认「图片 + 标题 + 正文」同屏且一致。
- **任何 failed 项只记 3 行到 cost_report.md，不自行多轮修复**；最终摘要仍 1-2 行。

## 成本控制（程序化，硬约束）
- **禁止调用任何积分查询 API**（查询本身扣点）；余额引用最近 cost_report.md；本日首行写 `预算: 300（未实时查询）`。
- 全流程工具调用上限：`memory_search 1 + webfetch ≤6 + websearch ≤2 + 读写文件若干 + runner 1`。超过即视为流程违规。
- 运行结束：runner 自动 append 完成时间与 verify 结果；模型只输出 1-2 行摘要。**不写复盘长文**。
- 纠错闭环：错误记 cost_report.md 3 行（现象/受影响条目/处置）；SKILL 升级由维护会话处理（本文件即维护会话产物）。

## 操作经验（V6.4 固化，避免绕路）
- **秒哒 CLI `chat` 的 `EXIT=1` 不代表业务失败** → 以轨迹 JSONL（traj.log）中的"改动点 + lint 通过 + 部署成功 + 版本号"判定，不因退出码重发指令。`chat` 必须同时带 `--app-id app-dbhlf1n9e3up` 与 `--context-id conv-dbhlf1n9e3uo`。
- **GitHub MCP**：单文件 `get_file_contents` 易 `TypeError` → 只读场景用**列目录**拿 sha/size；`create_or_update_file` 首次可能报 `Tool not found`/502（瞬时错误）→ 先 `browse` 列工具再**原样重试**即可；发送大内容前可用小探针文件验证 `\n`/`\"` 转义（返回 size 与本地 `wc -c` 比对），探针用完立即删除。
- **秒哒部署生效判据**：轨迹日志"部署成功"+versionId；**不要**用 CDN 源码 zip 快照判断（会拿到改前快照）。
- **秒哒端 create-draft 固定校验 5 张图**；不足 5 张时由 runner 复制最后一张真实图补足。

- V6.5（2026-10-25）：**第N次运行原则（窗口/去重/替榜）固化**——①搜索窗口以运行时刻为准，回溯至「前一天最后一次运行时刻」，前一天无运行则用「前两天最后一次运行时刻」，**上限前三天(T-3)**；②**当天新闻不去重、前一天新闻去重**（去重集 = glob 全部历史 `*旅游/news_data.json`）；③按「热度影响 + 在榜持续时间」排序，**同日多次运行发现更持久更热事件即替换掉榜条目**；④发现更优进程立即固化并同步 GitHub/秒哒，保证下次 ≤300 积分。适用范围：所有资讯类 skill（本 SKILL 为范本）。
- V6.4（2026-10-25）：**主路径改造 + 经验固化**——①选题由 websearch 泛词改为 **webfetch 直取权威本地源**（whnews.cn / weihai.iqilu.com），websearch 降为 ≤2 次补充；②配图改为**从权威正文页直取**，取消图片搜索通道；③工具口径重定义为 `memory_search 1 + webfetch ≤6 + websearch ≤2 + runner 1`（webfetch 不计搜索积分）；④去重改为 glob 扫描全部 `*旅游/news_data.json`；⑤标注废弃源（whnews 文旅频道陈旧、v.iqilu 视频页仅导航壳）；⑥固化秒哒 CLI/GitHub MCP 经验；⑦body 口径放宽为约 100-130 字。
